# Yu-s_DLife
My hobby account site.（https://divaclarice321.com）

## 写真を追加・差し替えるとき
1. 写真を `images/` に入れる（JPG または PNG）
2. 次を実行して、表示用の軽量版（`images/opt/`）を作る
   ```
   python3 tools/optimize_images.py
   ```
   - 表示サイズ別（横幅 160 / 480 / 960 / 1600px）の WebP を作ります
   - 位置情報などのメタデータは軽量版に残りません。元写真に位置情報があれば、画質を変えずに削除します
   - 必要なもの: Python 3 と Pillow（`pip install Pillow`）
3. ページからは `images/opt/<元のファイル名>-<横幅>.webp` を参照する

PR を作ると、軽量版の作り忘れ・位置情報入りの写真・撮影者情報や透かしの入れ忘れがないかを GitHub が自動でチェックします（「画像チェック」）。

## 撮影者の証拠（ページには表示されません）
写真が無断で使われたときに、撮影者が運営者であることを示すための仕組みです。設定は `tools/provenance.py` の冒頭にあります。

| 仕組み | 入る場所 | 説明 |
|---|---|---|
| 情報欄への記入 | 元写真・軽量版 | EXIF / XMP に `Yu (@DivaClarice321)` と著作権表記。元写真は画質を変えずに追記（撮影日時・機種・シリアル番号はそのまま） |
| 見えない透かし | 軽量版のみ | 画素をごくわずかに変えた模様。目では分からず、縮小・再圧縮・スクリーンショットでも検出できる（大きく切り抜かれると検出できないことがある） |
| 指紋（ハッシュ値）の記録 | `provenance/` | 写真ごとの SHA-256 の一覧。PR で GitHub に記録が残る |

- 写真を追加したら、`python3 tools/optimize_images.py` のあと `python3 tools/provenance.py manifest` を実行し、できた一覧も一緒にコミットしてください
  - 最後に表示される「一覧ファイル自体の指紋」を X などに投稿しておくと、第三者の日時の記録になります（任意）
  - 手元の RAW フォルダの指紋も記録できます: `python3 tools/provenance.py manifest --dir ~/Pictures/RAW --out ~/Pictures/provenance`
- 見つけた画像を調べる: `python3 tools/provenance.py check 画像ファイル`（撮影者情報・透かしの強さ・指紋の記録を表示）
- いちばん強い証拠は、**手元に残している RAW や未加工の元データ**です。消さずに保管してください
- 透かしの設定値（`WATERMARK_SEED`・`GRID` など）を変えると、それまでの画像の透かしを検出できなくなるので変えないでください

## ピンバッジを追加するとき
1. ピンの写真を `images/` に入れ、上の手順で軽量版を作る
2. `pins/data.json` に1件追加する（`Image` には元写真のパスを書けば、ページ側で自動的に軽量版を使います）
3. `"Draft": true` を付けたピンはサイトに表示されません（下書き・仮データ用）。公開するときは `false` にするか行ごと消す

ピンボードの大きさと列数は、登録点数に合わせて自動で調整されます。

**ピンの写真は「背景を透明にした PNG」（切り抜き）がおすすめです。** 影がピンの形どおりに落ちて、コルクに刺さっているように見えます。四角い写真のままでも表示できますが、写真カードを留めたような見え方になります。
ピンの傾き・少しのずれは Id から自動で決まり、同じピンはいつも同じ角度で表示されます。

コルク・木枠の質感画像（`assets/textures/`）は `python3 tools/make_textures.py` で作り直せます（外部素材は使っていません）。表示するピンが0点のときは「準備中」と表示されます。

**最初のピンを公開するとき**は、`pins/pins.html` の `<meta name="robots" content="noindex">` の行を削除し、`sitemap.xml` にピンボードの URL を戻してください（準備中の間は検索結果に出さない設定にしています）。

## ブログ記事を追加するとき（入稿フォーム）
記事は **GitHub の入稿フォーム1か所** から入れます。ファイル作成・写真の処理・ページの組み立て・公開はすべて自動です。

1. リポジトリの **Issues → New issue →「ブログ記事を入稿する」** を開く
2. タイトル・公開のしかた・本文を入れ、写真はドラッグ＆ドロップ（スマホの GitHub アプリからも可）
3. 「入稿の確認」にチェックして送信 → **送信した時点で公開を承認したものとみなします**（2026-10-14 管理者決定）
4. 数分後、結果がそのページにコメントで届きます（公開済みならページは自動で閉じます）

| やりたいこと | 方法 |
|---|---|
| すぐ公開 | 「公開のしかた」＝すぐに公開する |
| 予約投稿 | 「日時を指定して公開する」＋公開日時（日本時間）。1時間ごとの確認で公開され、公開時にコメントでお知らせ |
| 下書き保存 | 「下書きとして保存する」。サイトには出ません |
| 公開後に直す | 入稿ページの「…」→ Edit で直して保存（閉じたページでも可）。記事も自動で更新 |
| 非公開に戻す | Edit で「公開のしかた」を「下書きとして保存する」に変えて保存 |

- **Claude から入稿するとき**も、Claude が作った「入力済みの入稿フォームへのリンク」を開いて送信します（入口はこのフォーム1か所）
- 本文の書き方: 空行で段落、`## ` 見出し（2つ以上で目次が自動で付く）、`### ` 小見出し、URL だけの行はリンクカード、`> ` 引用、`- ` 箇条書き、`**太字**`、`[文字](URL)`。HTML は文字として表示されます
- 写真は GitHub に添付したものだけを使います（JPG・PNG。iPhone の HEIC は「設定 → カメラ → フォーマット → 互換性優先」で JPG に）。位置情報は自動で削除され、撮影者情報・透かしが自動で入ります
- 原稿は `content/blog/<URL名>/index.md`、組み立て結果は `blog/<URL名>/index.html`・`en/blog/…` などの言語版・`blog/posts.json`・`blog/feed.xml`・`sitemap.xml`（**手で編集しない**。直すときは入稿ページを Edit）
- 記事が1件も公開されていない間、一覧ページは検索結果に出ない設定（noindex）のままです。最初の記事が公開されると自動で外れます
- 仕組み: `.github/workflows/blog-intake.yml`（入稿）・`blog-publish.yml`（予約公開・毎時）→ `tools/blog_intake.py` → `tools/translate_blog.py`（翻訳）→ `tools/build_blog.py`

### ジャンル・タグ
- **ジャンル**はフォームの一覧から選びます（複数可）。一覧ページ上部のボタンで絞り込めます（`/blog/?genre=tdl` のように URL でも可）。記事がまだ無いジャンルのボタンは出ません
- **ジャンルを増やす・名前を変える**ときは `content/blog/genres.json` を編集して `python3 tools/build_blog.py` を実行し、PR にします（フォームの選択肢と一覧の絞り込みボタンが自動で更新されます）。`id` は URL に使うので、一度使ったら変えないでください
- **タグ**は自由入力（カンマ区切り）。記事の下に表示され、押すと同じタグの記事だけが一覧に出ます（`/blog/?tag=クラリス`）

### 自動翻訳（英語・フランス語・中国語）
- 「公開」「予約」で入稿すると、Claude API で記事（タイトル・説明・タグ・本文）を自動翻訳し、**言語ごとの URL** にページを作ります。翻訳した記事には「AI による自動翻訳です。日本語が原文です」と表示します

  | 言語 | 一覧 | 記事 | RSS |
  |---|---|---|---|
  | 日本語（原文） | `/blog/` | `/blog/<URL名>/` | `/blog/feed.xml` |
  | 英語 | `/en/blog/` | `/en/blog/<URL名>/` | `/en/blog/feed.xml` |
  | フランス語 | `/fr/blog/` | `/fr/blog/<URL名>/` | `/fr/blog/feed.xml` |
  | 中国語（簡体字） | `/zh/blog/` | `/zh/blog/<URL名>/` | `/zh/blog/feed.xml` |

- 各ページには、他の言語版の場所（hreflang）を書き、サイトマップにも全言語版を載せるので、海外の検索結果にはその国の言葉の版が出ます。SNS で共有したときのタイトル・説明もその言語になります
- 言語ボタンを押すと、その言語版のページへ移動します。サイト内を移動するときは前に選んだ言語の版を開きます（検索結果などサイト外から来たときは、開いたページの言語を優先）
- 翻訳結果は `content/blog/<URL名>/index.en.md` などに保存。原稿を直すと次の入稿・編集のときに翻訳し直し、それまではその言語のページを作りません（日本語版で「日本語のみ」と表示）
- 写真・URL・見出しの数が原文と合わない翻訳は保存しません。入稿ページを Edit でそのまま保存し直すと、もう一度翻訳します
- `en/`・`fr/`・`zh/` フォルダのページは `tools/build_blog.py` が `blog/index.html` から自動で作ります（**手で編集しない**）。メニューやフッターの訳は、各部品の `data-en` などの属性から入ります
- **準備**: Claude API のキーを、リポジトリの Settings → Secrets and variables → Actions → **New repository secret** に `ANTHROPIC_API_KEY` という名前で登録します。未登録の間は翻訳せず、日本語だけを表示します
- 使うモデルを変えるときは、同じ画面の Variables に `BLOG_TRANSLATE_MODEL` を登録します（未登録なら `tools/translate_blog.py` の既定値）
- 下書きは翻訳しません（費用がかからないように）

**注意**
- 動くのはリポジトリの持ち主本人が送信・編集したときだけです
- 予約・下書きの原稿も公開リポジトリには置かれるため、GitHub 上では公開日時より前に読めます
- 公開リポジトリでは60日間動きがないと予約公開の定期実行が止まります（Actions 画面から再開できます）
- main にブランチ保護（直接 push 禁止）を設定すると自動公開が止まります。設定するときは開発担当に相談してください
- 現行ドメインには広告・アフィリエイトリンクを置かないルールです（収益化は別ドメインで行う予定）

## Acorn Club（クラリスの新着グッズ情報のタイムライン）
`/acorn-club/` は、クラリスの新しいグッズ・ピンバッジ・ぬいぐるみの情報を自動で集めて、新しい順に表示する非公式・非営利のファンページです。

- **自動収集**：2時間ごとに `content/acorn/sources.json` の取得元（ニュース検索・情報サイトの RSS）から集めます（`.github/workflows/acorn-collect.yml` → `tools/acorn_news.py`）
  - 載せるのは **タイトル・リンク・掲載元・日付だけ**。記事の本文や写真は保存も表示もしません
  - 「クラリス / Clarice / 克拉莉丝」＋ディズニーの話題＋グッズの話題がそろうものだけ。日本語・英語・中国語・フランス語のニュース検索で、上海・香港・パリなど海外パークの情報も集めます。『カリオストロの城』『羊たちの沈黙』など別作品のクラリスは除きます
  - 約10年分まで残し、ページでは年（西暦）ごとに選んで見られます（最大1000件）
- **2つのタイムライン**：「グッズ・新商品」（ピンバッジ・ぬいぐるみ・グッズ）と「グリーティング・ショー」（グリーティング・ショー・パレード・イベント）。ページ上部のタブで切り替え（`/acorn-club/?view=appear` で直接開けます）
- **X の投稿（有料の X API、今は停止中）**：「クラリス＋新商品などの言葉（またはグリーティング等）＋画像付き、リポスト除く」の投稿を集める仕組みがあります。使い始めるときは
  1. X の開発者サイトで登録し、支払い方法と使いすぎ防止の上限を設定
  2. リポジトリの Settings → Secrets and variables → Actions に **Secret** `X_BEARER_TOKEN`（X のキー）を登録
  3. 同じ画面の **Variables** に `X_MONTHLY_POST_LIMIT`（月に読む投稿の上限。未設定なら 1300 件 ≒ 約1,000円）を登録
  - 保存するのは投稿の ID・日付・言語・種類だけで、表示は X の公式の埋め込みです。ページでは最初はリンクだけを出し、閲覧者が「X の投稿を表示する」を押したときだけ X に接続して画像付きで表示します
  - PR での試し取得では、費用がかからないよう X は読みません
- **手で追加**（SNS の投稿など、自動で集められないもの）：Issues → New issue →「Acorn Club に情報を追加する」。URL とひとことを入れて送信すると、数分でタイムラインに載ります（送信＝承認）。外すときは同じページを Edit して「掲載をやめる」にチェック
- **表示したくない情報**：`content/acorn/exclude.json` に URL か言葉を書いて PR にします
- **取得元を増やす・減らす**：`content/acorn/sources.json` を編集して PR にすると、PR 上で実際に取得を試した結果（取得元ごとの件数）が表示されます
- **公式の情報源のリンク**（ページ下部）：`content/acorn/links.json`
- 画面：`acorn-club/index.html`・`assets/acorn.css`・`assets/acorn.js`。初めて開いたとき（同じタブで1回だけ）に葉っぱの幕が開く演出があります。動きを減らす設定の端末では出ません
- デザインは原作の映像・キャラクターの絵・ロゴ・書体を使わないオリジナルです（どんぐり・樫の葉・電球の看板・ビロードの幕）。**キャラクターの絵や作品の画像を追加しないでください**
- 検索結果には出さない設定（noindex）のままです（法務の確認後に外します）

## フッター・「ホームに戻る」ボタン（全ページ共通の部品）を変えるとき
1. `tools/partials/footer.html`（フッター）または `tools/partials/home-button.html`（右上のボタン）を編集する
2. 次を実行して全ページへ反映する（2行目で、言語ごとのブログ `/en/blog/` なども作り直します）
   ```
   python3 tools/apply_partials.py
   python3 tools/build_blog.py
   ```
- 見た目（色・位置）は `assets/common.css` で変えられます
- 各ページの `<!-- partial:footer -->` 〜 `<!-- /partial:footer -->` の間は自動で上書きされるので、直接編集しないでください
- 新しいページを作るときは、`<head>` に `<link rel="stylesheet" href="/assets/common.css">` を入れ、`</body>` の前に次の2行を入れてから上のスクリプトを実行してください
  ```
  <!-- partial:footer -->
  <!-- /partial:footer -->
  ```
- PR を作ると、反映漏れがないかを GitHub が自動でチェックします（「共通部品チェック」）
